# Формат пользовательского проекта

Каждый проект — отдельная локальная папка. Пользователь работает с ней через приложение, а не редактирует JSON вручную.

```text
Projects/
└── ProjectName/
    ├── project.json
    ├── script/
    ├── audio/
    ├── source/
    ├── analysis/
    ├── clips/
    ├── timeline/
    └── export/
```

## Назначение папок

| Путь | Назначение | Этап |
| --- | --- | --- |
| `project.json` | Внутреннее состояние и относительные пути. | 1 |
| `script/` | Импортированный/сохранённый текст сценария. | 1 |
| `audio/` | `001.mp3` … `N.mp3` и тестовое аудио. MP3 удалённых сегментов сохраняются в `audio/retired/`. | 1 |
| `source/` | Ссылка на исходный фильм по умолчанию; при будущей явной функции копирования — копия файла. | 2 |
| `analysis/` | Транскрипт, субтитры, сцены, индекс, thumbnails и embeddings. | 2–3 |
| `clips/` | Материалы, если физическая нарезка станет нужна для экспорта. | 4 |
| `timeline/` | Сохранённая последовательность аудио и видеофрагментов. | 4 |
| `export/` | Итоговый `final.mp4`. | 4 |

## Минимальное состояние этапа 1

`project.json` хранит имя и версию формата проекта, выбранные настройки TTS, актуальный текст сценария, счётчик следующего ID и сегменты. После ручной правки сегментов актуальный текст собирается из них. У сегмента есть стабильный идентификатор, порядковый номер, текст, признак исключения из озвучки, статус, относительный путь к MP3, длительность в секундах и настройки, с которыми создано аудио; при ошибке дополнительно сохраняется её причина.

Пример концептуальной записи:

```json
{
  "segment_id": 1,
  "order": 1,
  "text": "Текст сегмента.",
  "excluded_from_tts": false,
  "status": "ready",
  "audio": "audio/001.mp3",
  "duration": 5.24
}
```

Пути артефактов всегда относительны к папке проекта. Номер MP3 пересчитывается предсказуемо после операций разделения, объединения или удаления; пользовательские ссылки должны обновляться вместе с состоянием, а не оставаться «висячими».

### Статусы и восстановление

Статусы сегмента: `ready`, `needs_tts`, `stale`, `excluded`, `file_missing`, `error`. Проигрывать и использовать в дальнейшем конвейере можно только `ready`. Изменение текста либо общих настроек TTS делает старое аудио `stale`, но не удаляет MP3. При исключении реплики готовый MP3 сохраняется и возвращается в `ready` после обратного включения, если ничего не изменилось.

При подтверждённой пересегментации готовое аудио сохраняется только у сегментов с теми же словами, пунктуацией и настройками TTS. Разрешены технические отличия: пробелы по краям и вид перевода строки. Остальные сегменты получают статус устаревшего или требующего создания аудио.

Запись `project.json` атомарна. Перед заменой валидного файла сохраняется предыдущая версия `project.json.bak`. Если основной JSON повреждён, приложение предлагает восстановить резервную копию: повреждённый файл сохраняется рядом как `project.json.corrupt-...`, а рабочее состояние восстанавливается в `project.json`. При отсутствии валидной копии приложение показывает ошибку, не создавая пустой проект поверх данных.

## Монтаж и экспорт

Начиная с формата 4, `project.json` содержит `timeline_state` — ссылку на `timeline/timeline.json` и отпечаток фильма. В формате 5 строка timeline также хранит признак пользовательской правки: синхронизация может заполнить старую пустую строку, но не заменяет осознанно изменённый монтаж.

## Кэш анализа видео

После анализа `analysis/` содержит `transcript.json`, `subtitles.srt`, `scenes.json`, активную неизменяемую ревизию `video_index-<revision>.json` и её кадры в `thumbnails/<revision>/`. Индекс хранит три опорных кадра каждой сцены, отдельные визуальные подписи и embeddings, а также флаг полной готовности. Незавершённая ревизия сохраняется отдельно в `video_index.partial.json` для продолжения и никогда не подменяет активную. После успешной атомарной записи новая ревизия становится активной только вместе с её ссылкой в `project.json`.

Ключ кэша связывает результат с конкретным исходным файлом, версией моделей, таймингами сцен и текстом субтитров. Ручные совпадения и признак использования локального контекста сохраняются в `segment_matches`; контекст не выходит за пределы текущего фильма. Если сохранённая ссылка на исходный файл недоступна, приложение требует повторно выбрать его и не подменяет файл автоматически.

## Видео, субтитры и сцены

Начиная с формата 5, `video_source.parts` хранит упорядоченный список внешних MP4/MKV со своими SHA-256 и метаданными. Агрегированный источник содержит общий отпечаток и суммарную длительность; старый одиночный источник мигрирует в список из одной части. Сцены и фрагменты содержат `source_index`, а их `start`/`end` относятся к общей временной шкале. Выбор кадра хранит происхождение подтверждения: `automatic`, `manual` или `bulk`.

При смене состава фильма текущие результаты переносятся в `analysis/retired/` и не используются. Кэш визуального анализа неизменённых частей остаётся в `analysis/part-cache/`. Форматы 1–4 открываются с миграцией в памяти и становятся форматом 5 при следующем сохранении; перед заменой сохраняется `project.json.bak`.
