# Архитектура

Narezchik — локальное Python desktop-приложение без сервера и базы данных-сервера. Архитектура должна оставаться маленькой, но отделять UI, продуктовые сценарии, данные проекта и внешние инструменты:

```text
PySide6 UI
↓
Core use cases
↓
Project / domain models and services
↓
Filesystem, Edge TTS, FFmpeg/ffprobe, later local AI tools
```

```text
src/narezchik/
├── ui/          # Окна, вкладки, виджеты и отображение статусов
├── core/        # Сценарии пользователя: проект, озвучка, анализ, монтаж
├── models/      # Типизированные модели и сериализация project.json
├── services/    # Файлы, TTS, медиаплеер, FFmpeg/ffprobe и будущие AI-адаптеры
└── main.py      # Сборка приложения и старт окна
```

## Правила границ

- `ui` показывает данные и передаёт пользовательские действия в `core`; он не вызывает внешние программы и не пишет JSON напрямую.
- `core` координирует сценарии, проверяет допустимость операции и обновляет модели проекта.
- `models` определяют переносимый формат состояния; они не знают о PySide6 и внешних процессах.
- `services` инкапсулируют файловую систему и интеграции. FFmpeg/ffprobe, Edge TTS, Whisper, PySceneDetect и локальные модели должны быть заменяемыми адаптерами, а не зависимостями UI. Тяжёлые видео-зависимости импортируются только при запуске соответствующей операции.
- Автосохранение выполняется после успешного изменения состояния. Дорогой результат считается готовым только после наличия валидного файла и соответствующих данных в `project.json`.

## Наращивание по этапам

На этапе 1 нужны только проект, сценарий, сегменты, Edge TTS и ffprobe. Модули видео, транскрипции, сцен, embeddings, сопоставления, timeline и экспорта добавляются только в соответствующих этапах `TASKS.md`. Не создавать заранее пустые абстракции, контейнеры зависимостей или event bus.
