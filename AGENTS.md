# Инструкции для AI-агентов

## Рабочий стандарт

- Отвечайте на языке пользователя.
- Сначала изучайте проект и актуальную задачу, затем принимайте технические решения, реализуйте, проверяйте и сообщайте результат.
- Пользователь определяет желаемое поведение продукта. Агент определяет техническую реализацию, структуру файлов, библиотеки и проверки.
- Не переносите рутинный технический выбор на пользователя. Спрашивайте только о решениях, которые меняют продукт, пользовательский опыт, стоимость, безопасность или необратимо затрагивают данные.
- Опираться на факты из кода, документации, тестов и вывода запуска, а не на предположения.
- Берегите несвязанные изменения пользователя. Не отменяйте, не переформатируйте и не удаляйте чужую работу без явного запроса.
- Выбирайте минимально достаточную архитектуру. Не создавайте слои, абстракции и зависимости без текущей необходимости.
- Не ломайте работающий сценарий ради локального исправления. Исправляйте владеющий проблемой слой.
- Не объявляйте работу завершённой без проверки результата.

## Перед серьёзной задачей

Прочитайте по порядку:

1. `AGENTS.md`
2. `PRD.md`
3. `CHECKLIST.md`
4. `TASKS.md`
5. Документы из `docs/`, относящиеся к задаче.

Затем изучите затрагиваемый код и его тесты. Доверяйте текущему коду и фактическому поведению больше, чем устаревшему описанию; при необходимости обновите документацию.

## Границы проекта

Это локальное desktop-приложение на Python для автоматизации видеопересказов. Основной стек: Python, PySide6, Edge TTS и FFmpeg/ffprobe. В дальнейшем допустимы faster-whisper, PySceneDetect, OpenCV, локальные embeddings и локальные vision-модели.

- Платные API не являются обязательной частью продукта.
- Не добавляйте серверную часть, базу данных-сервер, веб-приложение, мобильное приложение, аккаунты, платежи или облачное развёртывание, пока продукт явно не потребует этого и `CHECKLIST.md` не будет обновлён.
- Данные пользовательского проекта хранятся локально в его папке; формат описан в `docs/PROJECT_FORMAT.md`.
- Не начинайте Whisper, анализ сцен и автоматический монтаж до завершения и проверки первого функционального этапа из `TASKS.md`.

## Реализация и проверка

- Для нетривиальной задачи сначала определите изменяемое поведение и основной наблюдаемый сигнал успеха.
- Предпочитайте стандартную библиотеку и уже объявленные зависимости новым пакетам.
- Пишите тест на устойчивой минимальной границе: чистые правила — модульные тесты, интеграции с файлами и внешними программами — изолированные интеграционные тесты.
- После реализации обязательно:
  1. запустите тесты;
  2. проверьте запуск desktop-приложения;
  3. вручную или автоматически проверьте изменённый пользовательский сценарий;
  4. исправьте найденные ошибки;
  5. только после этого считайте задачу выполненной.
- Если обязательная проверка не может быть выполнена, честно укажите причину и лучшую доступную замену; не называйте задачу полностью выполненной.

## Документация и отчёт

- Обновляйте `PRD.md`, `CHECKLIST.md`, `TASKS.md` и документы в `docs/`, когда меняются продуктовый контракт, архитектура, формат проекта или способ запуска.
- В отчёте кратко укажите изменения, выполненные проверки, их результат и оставшиеся риски либо следующий шаг.
